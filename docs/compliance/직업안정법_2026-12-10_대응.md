# 직업안정법 제25조 개정(2026-12-10 시행) 대응 — 잇닿

작성 2026-11-03. 잇닿(케셰르)은 **직업정보제공사업 신고 사업자**라 제25조 준수사항의 의무 주체다. 법률 제21787호(2026-06-09 공포)로 신설·개정된 항목이 **2026-12-10**부터 적용된다. 하위 법령(시행령·시행규칙의 모니터링 세부 기준)은 시행 전 한 번 더 확인한다.

## 1. 법이 요구하는 것 ↔ 잇닿 현재 ↔ 11/03 보완

## 2. 국세청 사업자 상태조회 키 — ✅ 2026-11-03 등록 완료

운영 env `NTS_BUSINESS_API_KEY` 등록·관리자 앱 재배포 후, 운영 서버가 잇닿 사업자번호를 조회해 '계속사업자 · 부가가치세 일반과세자' 응답 확인(진단 경로 `/api/cron/nts-probe`, 시스템 점검 '국세청 사업자 조회' 정상). 키를 다시 넣을 일이 생기면 아래 절차를 따르되, **`pbpaste` 로 넘기지 말 것**(명령을 복사하는 순간 클립보드가 덮여 명령 텍스트가 들어간 적 있음). 키를 명령에 직접 넣거나 `read -rs` 프롬프트로 받는다. 코드는 Encoding·Decoding 키를 모두 받는다.

1. [공공데이터포털](https://www.data.go.kr) 로그인(케셰르 사업자 계정 또는 개인) → 검색 **"국세청_사업자등록정보 진위확인 및 상태조회 서비스"** → **활용신청**(개발계정, 일 1만 건, 자동승인).
2. 마이페이지 → 데이터 활용 → Open API → 활용신청 현황 → 해당 서비스 → **일반 인증키** 복사(세 번 클릭으로 한 덩어리 선택). Encoding·Decoding 어느 형태든 된다.
3. 터미널:
   ```bash
   cd ~/atman/apps/admin-web && vercel env add NTS_BUSINESS_API_KEY production
   # 붙여넣기 → 엔터. 그다음 관리자 앱 재배포
   vercel --prod --yes
   ```
4. 확인: CRON_SECRET 으로 `GET /api/cron/nts-probe` → `keyShape.length` 88·`status: active` (DB 쓰기·알림 없음). 운영자는 /ops/facilities 등록 심사 카드의 **다시 조회**로도 확인. 이후 cron(`/api/cron/expire-shifts`)이 하루 30곳씩, 30일 지난 사업장을 자동 재조회한다. 로컬 `.env.local`에도 같은 키를 넣으면 로컬에서도 조회된다.

## 3. 운영 절차(월간 루틴)

- **사업장 승인(수시)**: 등록증 이미지와 제출 번호 대조 → 국세청 '계속사업자' 확인 → 상호·주소가 심평원 자료와 일치 → 승인. 어긋나면 반려 사유에 그대로 적는다.
- **공표 정보 대조(매월 1일, 10분)**: /ops/facilities → "구인자 공표 정보 대조" 목록의 각 사업장을 (a) 고용노동부 [체불사업주 명단공개](https://www.moel.go.kr/info/defaulter/defaulterList.do)에서 상호·사업자등록번호로 검색, (b) 연 1회(보통 연말) 고용노동부 보도자료 "산업재해 발생건수 등 공표" 목록과 대조 → 해당하면 체크, 아니면 메모에 "YYYY-MM 명단 없음" → **대조 완료로 저장**(35일 넘으면 '대조 필요' 배지). 저장 즉시 근무자 화면에 게재된다.
- **신고 검토(접수 후 2영업일 내)**: /ops/safety "공고·사업장 신고" → 공고 조건·사업장 정보 확인 → 필요하면 사업장에 연락해 정정 요청, 허위가 확인되면 같은 카드의 **'게재 중지'**(사유 입력 → 한 번 더 확인)로 그 사업장 공고를 목록·지도·공개 페이지에서 내리고 새 공고·공개 전환을 막는다(해제 가능, `audit_logs` `facility.posting.suspend/resume`) → 검토 상태·처리 기록 저장. '사업장 관리자 신고' 배지가 붙은 건은 경쟁 사업장 보복 신고일 수 있어 사실 확인을 먼저. 신고자 정보는 사업장에 알리지 않는다. 신고 기록은 1년 보관 뒤 매일 03:50 cron 이 지운다(`job-posting-report-retention`).
- **신규 공고 모니터링(주 1회)**: 사장님 앱 `/ops` 계열 화면에 신규 공고 목록이 없으므로, 당분간은 운영 DB에서 최근 7일 공고를 조회해 시급·근무시간·설명을 훑는다(최저임금 미만은 이미 코드에서 거부). 공고가 주 50건을 넘기면 운영자용 "최근 공고" 화면을 만든다.

## 4. 기록·증빙

- 승인·반려·공표 플래그 변경·게재 중지/해제는 `audit_logs`(`facility.self_registration.*`, `facility.public_flags.update`, `facility.posting.suspend/resume`)에 남는다. 기록을 못 남기면 변경을 되돌린다.
- 국세청 조회 결과는 `facilities.business_status*`, 신고는 `job_posting_reports` 에 남는다.
- 점검 요청이 오면 이 문서 + audit_logs 추출로 대응한다.
