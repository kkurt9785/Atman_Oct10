# 직업안정법 제25조 개정(2026-12-10 시행) 대응 — 잇닿

작성 2026-11-03. 잇닿(케셰르)은 **직업정보제공사업 신고 사업자**라 제25조 준수사항의 의무 주체다. 법률 제21787호(2026-06-09 공포)로 신설·개정된 항목이 **2026-12-10**부터 적용된다. 하위 법령(시행령·시행규칙의 모니터링 세부 기준)은 시행 전 한 번 더 확인한다.

## 1. 법이 요구하는 것 ↔ 잇닿 현재 ↔ 11/03 보완

## 2. 국세청 사업자 상태조회 키 — 사용자 손 (10분)

1. [공공데이터포털](https://www.data.go.kr) 로그인(케셰르 사업자 계정 또는 개인) → 검색 **"국세청_사업자등록정보 진위확인 및 상태조회 서비스"** → **활용신청**(개발계정, 일 1만 건, 자동승인).
2. 마이페이지 → 해당 서비스 → **일반 인증키(Decoding)** 복사. 코드가 `encodeURIComponent` 로 감싸므로 Encoding 키를 넣으면 안 된다.
3. 터미널:
   ```bash
   cd ~/atman/apps/admin-web && vercel env add NTS_BUSINESS_API_KEY production
   # 붙여넣기 → 엔터. 그다음 관리자 앱 재배포
   vercel --prod --yes
   ```
4. 확인: admin.itdot.co.kr/ops/facilities 의 등록 심사 카드에서 **다시 조회** → "계속사업자"가 떠야 한다. 이후 cron(`/api/cron/expire-shifts`)이 하루 30곳씩, 30일 지난 사업장을 자동 재조회한다. 로컬 `.env.local`에도 같은 키를 넣으면 로컬에서도 조회된다.

## 3. 운영 절차(월간 루틴)

- **사업장 승인(수시)**: 등록증 이미지와 제출 번호 대조 → 국세청 '계속사업자' 확인 → 상호·주소가 심평원 자료와 일치 → 승인. 어긋나면 반려 사유에 그대로 적는다.
- **공표 정보 대조(매월 1일, 10분)**: /ops/facilities → "구인자 공표 정보 대조" 목록의 각 사업장을 (a) 고용노동부 [체불사업주 명단공개](https://www.moel.go.kr/info/defaulter/defaulterList.do)에서 상호·사업자등록번호로 검색, (b) 연 1회(보통 연말) 고용노동부 보도자료 "산업재해 발생건수 등 공표" 목록과 대조 → 해당하면 체크, 아니면 메모에 "YYYY-MM 명단 없음" → **대조 완료로 저장**(35일 넘으면 '대조 필요' 배지). 저장 즉시 근무자 화면에 게재된다.
- **신고 검토(접수 후 2영업일 내)**: /ops/safety "공고·사업장 신고" → 공고 조건·사업장 정보 확인 → 필요하면 사업장에 연락해 정정 요청, 허위가 확인되면 등록 심사 화면에서 승인 취소(공고 차단) → 검토 상태·처리 기록 저장. 신고자 정보는 사업장에 알리지 않는다. 신고 기록은 1년 보관(`expires_at`).
- **신규 공고 모니터링(주 1회)**: 사장님 앱 `/ops` 계열 화면에 신규 공고 목록이 없으므로, 당분간은 운영 DB에서 최근 7일 공고를 조회해 시급·근무시간·설명을 훑는다(최저임금 미만은 이미 코드에서 거부). 공고가 주 50건을 넘기면 운영자용 "최근 공고" 화면을 만든다.

## 4. 기록·증빙

- 승인·반려·공표 플래그 변경은 `audit_logs`(`facility.self_registration.*`, `facility.public_flags.update`)에 남는다.
- 국세청 조회 결과는 `facilities.business_status*`, 신고는 `job_posting_reports` 에 남는다.
- 점검 요청이 오면 이 문서 + audit_logs 추출로 대응한다.

## 5. 남은 결정·후속

1. 체불사업주 명단 **자동 대조**(명단 CSV를 월 1회 가져와 사업자등록번호 매칭) — 사업장이 50곳을 넘기 전까지는 수동으로 충분.
2. 시행규칙(모니터링 방법·주기)이 고시되면 3절 주기를 맞춘다.
3. 약관·개인정보처리방침과 함께 **변호사 검토**(기존 과제)에 이 문서를 포함한다.
4. 배포 순서: ① 사용자 `cd ~/atman && supabase db push --linked --dry-run` 확인 후 `supabase db push --linked` ② Kurt 두 앱 `vercel --prod` ③ /ops/facilities·/ops/safety·근무자 사업장 시트 확인.
