- 캡처: 헤드리스 Chrome(CDP) 390×844 @2x. 디버그 포트는 실행마다 빈 포트를 고르고(다른 Chrome 세션과 안 부딪힘), 끝나면 그 Chrome 을 종료한다. `*-live`는 운영 도메인, 인자 없으면 localhost:3002/3003.
- 운영 화면은 비동기로 불러오므로 스크립트가 기대 문구(`waitFor`)가 뜰 때까지 기다린 뒤 찍는다. 못 찾으면 `WAIT_TIMEOUT` 경고만 남기니 로그를 볼 것.
- 렌더: 장면 길이 = 나레이션 길이(최소 4초). 장면 전환은 0.16초 slideleft. 1080×1920 30fps h264 + aac. 화면은 폭 820으로 줄여 가운데 둔다.
- 시연 데이터: **2026-11-05부터 공개 시연 계정(`@demo.atman.co.kr`)의 '시연 초기화'는 막혀 있고, 데이터는 매일 08:30 자동 재생성**된다. 그날 QA·방문자가 남긴 흔적(알림·대화·근태)이 프레임에 찍힐 수 있으니 반드시 본다. `revive_demo.py`·SQL 은 쓰지 않는다.
- **UI 문구·흐름을 바꾼 배포 뒤에는 반드시 재캡처** — 영상이 구화면을 보여주면 시연 신뢰가 깨진다. (2026-08-26 렌더본이 9/4·9/7 변경분을 못 담은 사례)

### 단기 캡처 주의 — 운영 DB 쓰기와 '이미 수락' 상태

- `worker-gig-live`는 **운영 DB에 쓴다**(`https://itdot.co.kr/api/demo-login` `GIG2026`). `reset_gigworker_invite_demo` → 긱 시연 사업장의 지급·계좌 전달·근태·인증 로그·알림, 워크룸 공지·대화·출석 확인, 방문자가 만든 초대·근무자·빈 근무 건을 지우고 고정 초대를 새로 만든 뒤, 브라우저에서 **초대 수락**(`claim_facility_staff_invite`·계좌 전달·조건 스냅샷)까지 누른다. 출근은 누르지 않는다. 시연 계정·시연 사업장(`DEMO-GIGWORKER-2026`) 데이터만 건드리지만, 그 시각 다른 사람의 단기 시연은 지워진다. `public-live`는 공개 페이지만 열어 쓰기 없음.
- **'이미 수락' 상태가 풀리지 않는 문제(2026-11-05 확인).** 초기화는 '진행 중인 시연'(고정 근무자 행 `updated_at` 1시간 이내, 또는 근무 중·퇴근 1시간 이내)이면 건너뛴다. 그런데 15분 크론 `refresh_demo_worker_readiness`(시연 계정 로그인 때 `prepare_my_demo_worker`도 같은 함수)가 **오늘 근태가 없는 고정 근무자 행의 `updated_at`을 계속 갱신**하고, 08:30 정리(`cleanup_gig_demo_facility`)는 고정 행의 연결을 풀지 않는다. 그래서 누군가 한 번 수락하면 그 뒤 모든 방문자의 `/gig/demo`가 초대 화면 없이 바로 근무 화면으로 간다(근태·지급 탭의 "2026-10-14에 수락한 조건 그대로예요"도 그대로 — 초기화가 `terms_snapshot`을 지우지 않음). 캡처 스크립트는 이때 `GIG_RESUME` 경고를 내고 `00-gig-invite`를 찍지 않는다.
  - 캡처를 위해 푸는 법(시연 데이터만, 이번에 쓴 방법): 사장님 시연 `admin.itdot.co.kr/login?demo=gigworker` → 근태 '오늘 근무자' → 긱워커 데모 카드 '사장님이 직접 처리' → **출근 → 퇴근**. 오늘 근태가 생기면 크론이 그 행을 건드리지 않으니 **퇴근 1시간 뒤** `worker-gig-live`를 다시 돌리면 초기화된다(그 근태도 초기화가 지운다).
  - 근본 수정(제안, 미적용): 크론이 연결된 고정 행은 `updated_at`을 건드리지 않거나, 판정을 `updated_at` 대신 수락 시각·마지막 출퇴근 시각으로. 초기화 때 `terms_snapshot`도 비우기.
