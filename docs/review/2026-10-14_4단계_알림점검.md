# 4단계 — 알림 발송·알림함·팝업 점검

사용자 사용량 확인: 92%. 운영에는 읽기 전용 집계만 수행했다. 실제 사용자/데모 계정에 시험 알림을 보내거나 알림 큐를 실행하지 않았다. 변경 사항은 로컬이며 미배포다.

## 운영 상태 (조회 시점 기준)

`scripts/audit-notification-health.mjs`로 메시지 내용·계정·구독 주소·키를 출력하지 않고 집계했다.

| 항목 | 확인 결과 |
| --- | --- |
| 최근 7일 생성 알림 | 11건 |
| 발송 완료 상태 | 3건 |
| 푸시 구독이 없어 건너뛴 알림 | 8건 |
| 저장된 푸시 구독 | 3건 |
| 대기/실패/처리 중 적체 | 0건 |
| 재시도 8회 소진 후 미완료 | 0건 |

발송 완료는 공급자가 전송을 받아들였다는 상태이지, 특정 휴대폰에서 사용자가 팝업을 확인했다는 증거는 아니다. 로컬 환경에는 VAPID 공개키·개인키·subject·cron secret이 있으며 관리자 클라이언트 공개키와 서버 공개키가 일치했다. 배포 환경변수 일치 여부까지 검증한 것은 아니다.

## 수정

1. 푸시 구독 조회 오류를 미구독으로 간주해 알림을 폐기하던 것을 재시도 대상으로 변경했다. 실제 조회 결과가 빈 경우만 건너뛴다.
2. 발송 상태 저장 실패를 성공 건수로 보고하지 않는다. 일부 기기만 전송 성공한 경우에는 잔여 실패 사유를 남긴다.
3. 발송 payload에 알림 ID를 넣고 두 앱의 OS 알림 tag에 사용해 동일 알림의 재전송 팝업을 합친다. 정확히 한 번 전달을 보장하는 것은 아니다.
4. 두 앱의 서비스 워커는 잘못된 JSON에도 기본 알림을 표시한다. 알림함/OS 알림 클릭은 앱 내부 경로만 허용하며 외부 URL·역슬래시·제어문자를 거부한다.
5. 알림함 조회 예외 후 로딩이 끝나지 않는 문제와 읽음 저장 오류를 성공처럼 표시하던 문제를 수정했다. 읽음 저장 실패가 목적 화면으로 이동하는 것을 막지 않는다. 재시도 시 오래된 오류 안내를 지운다.
6. 근무지 필드가 없는 `/gig/settlement` 지급 알림도 긱 알림으로 분류한다. 긱 워커의 의료용 `/workroom` 목적지는 `/gig/workroom`으로 변환한다.
7. 워커 알림 제목을 한 줄 말줄임으로 자르지 않는다. 관리자 실시간 퇴근 팝업은 처리 완료를 단정하지 않고 요청 접수·승인 상태 확인으로 안내한다.
8. 워커 푸시 설정은 지원 여부·공개키 누락·로그인 만료를 명시적으로 처리하고 기존 기기 구독을 재사용한다. 권한 요청은 클릭 직후 실행하고 그 앞에 네트워크 조회를 두지 않는다.
9. 출퇴근 인증 실패에도 DB가 관리자 알림을 만들 수 있으므로 RPC 응답이 있으면 즉시 발송을 깨운다. 성공에만 한정하지 않는다.

## 검증

- 단위/회귀 테스트 총 74개 통과. 이번 알림 관련 추가 21개는 발송 실패 분류, URL 안전성, 두 서비스 워커의 팝업·클릭 핸들러, 긱 분류, 로그인 만료·권한 거절·권한 요청 순서를 포함한다.
- 두 앱 배포용 빌드와 타입 검사 통과.
- 실제 배포용 워커 앱의 360px·390px Chrome 화면에서 알림 조회 실패→재시도, 읽음 저장 실패 시 미읽음 유지→재시도 성공, 긴 제목 표시, 클릭 시 긱 근무지 대화 경로 이동을 검증했다. DB 응답과 외부 알림 요청은 모두 모의 처리했다. 출퇴근 회귀도 함께 통과했다.
- 서비스 워커 팝업 검사는 격리된 이벤트 실행으로 `showNotification`에 전달되는 제목·본문·tag를 확인했다. 실제 OS 알림 권한 창이나 휴대폰 푸시 수신 검증을 대체하지 않는다.
- 앱 알림함은 후속 마이그레이션 `20260828090000_manager_flow_reliability.sql`에서 푸시 미구독으로 건너뛴 건도 조회하도록 이미 변경되어 있다. 초기 마이그레이션만 보고 알림함 누락이라고 판단하지 않았다.

## 아직 필요한 출시 전 점검

- **실기기 수신**: iPhone 홈 화면 설치·Android·데스크톱 각각 허용/거절, 앱 실행/백그라운드/종료, 알림 클릭을 전용 테스트 계정으로 확인해야 한다. 이번에는 실제 발송하지 않았다.
- **재시도 주기**: 저장소의 Vercel 발송 cron은 일 1회이고, 발생 직후 nudge와 DB 10분 리마인더가 추가로 깨운다. DB 리마인더는 새 알림이 생성된 경우만 발송을 깨우므로 조용한 시간대의 재시도 지연 가능성이 남아 있다. 배포된 cron/Vault의 활성 상태도 확인해야 한다.
- **여러 기기**: 한 기기 성공 시 해당 알림은 sent다. 다른 기기의 일시 실패를 개별 재시도하려면 기기별 전달 이력이 필요하다.
- **계정 전환·로그아웃**: 브라우저 구독 존재만으로 현재 계정의 서버 등록이 정상임을 보장하지 않는다. 동일 기기에서 계정을 바꿀 때 구독 소유권 정리와 로그아웃 후 알림 노출을 별도 검증해야 한다.
- **여러 사업장 관리자**: payload의 사업장과 현재 선택 사업장이 다를 때 자동 전환하는 공통 목적지 처리가 필요하다. `/timesheet` 같은 상대 경로만으로는 항상 원래 사업장을 여는지 보장하지 못한다.
- 관리자 팝업은 근태 화면 전용이며 워커 전체 화면에 공통 인앱 토스트를 띄우는 구조는 아니다. OS 팝업·알림함·화면 내 승인 안내를 구분해 판매 시 설명해야 한다.

알림 전달 전체를 ‘정상 완료’로 판정하지 않았다. 운영 큐 적체 없음과 확인한 코드 경로/테스트 통과만 확인했다.
