# 잇닿 UI UX 반영 결과와 운영 적용 보류 항목

2026년 10월 14일 사용자 요청인 “크리티컬 한 거 아니면 모두 반영”에 따라 이번 검토에서 확인한 저위험 화면 개선을 로컬 코드에 반영했다. 운영 배포와 운영 DB 변경은 하지 않았다. 마지막 사용량 확인값은 90%이며, 다음 작업 전 사용자 확인이 필요하다.

## 이번에 반영한 화면 개선

| 영역 | 반영 내용 | 기대 효과 |
| --- | --- | --- |
| 워커 상단 탐색 | 알림·설정·근무 방식 선택의 터치 영역 확대와 키보드 초점 표시 | 작은 화면에서 오터치 감소 |
| 양쪽 앱 알림 목록 | 긴 제목과 날짜를 위아래로 배치하고 새로고침·재시도 터치 영역 확대 | 제목 잘림 감소와 재시도 편의 |
| 관리자 근태 수정 | 저장 중 입력 잠금, 중복 제출 방지, 저장 상태 안내 | 처리 중 재입력과 반복 저장 방지 |
| 관리자 지급 화면 | “이체 완료 기록”으로 변경하고 실제 송금은 앱 밖에서 해야 함을 안내 | 기록 기능을 송금 기능으로 오해하지 않도록 구분 |
| 지급 안내 | 알림 도착을 단정하지 않고 워커 앱에서 지급 내역 확인 가능함을 안내 | 전송 실패나 미구독 상황과 안내 문구 불일치 방지 |
| 지급 일정 선택 | 실제 동작에 맞게 “이번 주”를 “7일 뒤”로 변경하고 버튼 여백 확대 | 날짜 해석 오류 감소 |

주요 탐색 버튼은 44px 이상을 설계 목표로 적용했다. WCAG 2.2 AA의 최소 타깃 기준은 예외 조건을 포함한 24 CSS px이며, 44px를 AA 최소 기준이라고 해석하지 않는다. [W3C 타깃 크기 기준](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

저장 상태와 오류는 상태 메시지 역할을 사용해 보조 기술에서도 확인할 수 있도록 했다. 이번 변경만으로 전체 앱의 접근성 준수를 인증한 것은 아니다. [W3C 상태 메시지 기준](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)

## 검증 결과

- 워커·관리자 모두 배포용 빌드와 빌드 과정의 타입 검사를 통과했다.
- 자동 테스트 13개 파일, 86개 항목이 통과했다.
- 워커 모바일 360px·390px에서 각 14개, 총 28개 브라우저 회귀 검증 항목이 통과했다. 탐색 버튼 크기, 출퇴근 실패·재시도·중복 방지, 성공 안내, 알림 조회·읽음 저장 실패와 복구, 링크 이동, 가로 넘침을 확인했다.
- 알림 목록과 출근 성공 화면의 캡처를 직접 확인했다. 브라우저 검증은 모의 인증·응답을 사용했으며 운영 데이터 쓰기는 0건이다.
- 관리자 UI는 빌드 검증까지 완료했으며 실제 관리자 로그인 상태의 브라우저 검증은 남아 있다. 실제 휴대폰의 푸시 도착·잠금 화면 팝업도 별도 확인해야 한다.
- 변경 내역의 공백 오류 검사인 `git diff --check`를 통과했다.

## 운영 적용 전에 따로 확인할 항목

앞선 단계에서 작성한 아래 코드는 작업본에 남아 있다. 이번 요청의 저위험 UI 변경과 함께 일괄 배포하지 않는다.

| 변경 묶음 | 보류 이유 | 적용 전 조건 |
| --- | --- | --- |
| 지급 계산·원장 및 중복 지급 방지 | 금액과 과거 지급 호환성에 영향 | 기존 데이터 검증, DB·앱 호환 배포 계획, 동시성 검증 |
| 급여 접근 권한·데모 격리 | 사용자별 접근 범위 변경 | 실제 역할별 권한 회귀 검증 |
| 근태 수정·마감 원자성 | DB 함수와 잠금 규칙 변경 | 최신 전체 스키마 검증과 다른 쓰기 경로의 충돌 점검 |
| 데모 워커 15분 준비·초기화 작업 분리 | 운영 스케줄과 데모 데이터 생명주기 변경 | 현재 cron 목록·진행 중 시연 확인, 함수 설치 순서 검토 |
| 알림 전송·서비스 워커 변경 | 실제 기기 전송·재시도·링크 처리에 영향 | 테스트 계정의 허용·거부·미구독·백그라운드·다중 기기 검증 |

관련 상세 기록은 같은 폴더의 1단계부터 6단계 검토 문서에 있다. 신규 마이그레이션은 `20261014180000`부터 `20261014220000`까지이며 운영 적용 여부와 선행 마이그레이션 상태를 먼저 대조해야 한다.

현재 일부 파일에는 UI 수정과 앞선 업무 로직 수정이 함께 들어 있다. **UI만 배포할 때도 파일 전체 복사가 아니라 변경 구간 단위로 분리한 배포본을 만들어 재검증해야 한다.** 프로젝트와 무관한 기존 문서·이미지·사주 보고서 변경은 이번 배포 범위에서 제외한다.

판매 가능 수준으로 최종 승인하려면 실제 기기 알림 검증, 관리자 주요 화면 검증, 지급·권한·동시성 검증과 승인된 운영 배포가 남아 있다.
