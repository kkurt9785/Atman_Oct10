# 5단계 — 시연 중 자동 초기화 제거

시작 사용량: 사용자 확인 91%. 범위를 데모 자동 유지에 한정했다. 운영 배포, 운영 cron 변경, 실제 재시드는 실행하지 않았다.

## 방식

활성 세션을 계속 추적하며 파괴적 재시드의 실행 시점을 미루는 방식이 아니라, **자동 작업 자체를 비파괴 준비로 제한**했다. 시연자가 페이지를 열어 둔 채 자리를 비우거나 기기를 바꾸는 경우에도 세션 감지 실패 때문에 데이터가 자동 삭제되지 않는다.

- 기존 초기화/재생성/위치 변경 cron 10개를 `active=false`로 바꾸는 마이그레이션을 추가했다. 작업 정의·시간표·명령은 삭제하지 않아 필요하면 확인 후 복구할 수 있다.
- 2단계의 `demo-worker-readiness-15min`은 유지한다. 활동 상태와 표시된 시연 공고 시간을 갱신하며, 근태가 존재하는 공고와 실제 근무자 데이터는 변경하지 않는 기존 경계를 사용한다.
- 아침 서버 작업 `expire-shifts`의 전체 재시드를 제거했다. 시연 공고 시간을 먼저 준비한 후 일반 만료 처리를 한다. 준비 RPC가 실패하면 503으로 중단해 시연 공고를 먼저 취소하지 않는다. `DEMO_SHOWCASE_ENABLED=false`면 일반 만료 처리는 정상 수행한다.
- 수동 전체 초기화 `/api/cron/revive-demo`는 GET에 405를 반환한다. POST에서도 cron 인증과 `confirmReset: 'RESET_DEMO_DATA'`가 모두 필요하며, 데모 기능 비활성 상태에서는 실행하지 않는다.
- 운영 전환용 수동 정리 스크립트에도 누락된 데모 작업 이름을 추가했다. 이 스크립트는 이번에 실행하지 않았다.

## 비활성화 대상

`demo_showcase_refresh_0005kst`, `demo_clinic_workforce_refresh_0010kst`, `demo-pharmacy-workforce-daily`, `anchor-demo-showcase-daily`, `w_womens_showcase_every_3_hours`, `demo1-wf-application-daily`, `demo1-chat-showcase-daily`, `demo_worker_locations_00kst`, `demo_worker_locations_08kst`, `demo_worker_locations_16kst`.

## 검증

- 자동 테스트 81개 통과(기존 74개 + 자동/수동 경계 7개).
- 두 앱 타입 검사 통과. 변경된 관리자 앱 배포용 빌드 확인.
- 로컬 PostgreSQL/pg_cron에서 테스트 트랜잭션 실행: 10개 작업 비활성, 15분 준비 작업 유지, 무관한 운영 작업 유지, 기존 정의 보존, 마이그레이션 중복 실행 안전성을 확인하고 전부 ROLLBACK했다.
- 운영 DB에는 접근하거나 쓰지 않았다. 이번 변경은 화면 구성 변경이 없어 추가 모바일 스크린샷 검증은 하지 않았다.

## 반영·운영 주의

1. 전체 변경의 호환성을 고려한 배포 계획 아래, `20261014200000_demo_worker_readiness.sql`과 `20261014210000_non_destructive_demo_automation.sql`이 적용되어야 새 서버 경로가 작동한다. 필요한 RPC가 없으면 만료 배치는 의도적으로 실패한다.
2. 이미 시작된 DB cron 작업이나 구버전 서버 요청은 비활성화만으로 중단되지 않는다. 반영 시 진행 중 작업 유무를 확인하고 시연이 없는 시간에 전환해야 한다. 운영 작업 실행 기록은 이번 단계에서 조회하지 않았다.
3. 자동 준비는 기존 시연 공고를 갱신할 뿐 새 데이터를 무한 생성하지 않는다. 시나리오를 모두 완료했거나 새 달의 가상 근태가 필요하면 담당자가 시연 종료를 확인한 뒤 수동 재시드해야 한다.
4. 수동 초기화에는 활성 시연 감지/동시 실행 잠금이 아직 없다. 명시적 확인은 자동 실행 방지 장치이지 진행 중 세션 검증을 대체하지 않는다. 관리자 현장 시연의 별도 reset과 긱 데모의 기존 조건부 reset은 이번에 변경하지 않았다.
5. 새로운 이름으로 별도 등록된 운영 cron이나 외부 스케줄러까지 자동 탐지한 것은 아니다. 실제 배포 전 작업 목록과 위 10개 이름을 대조해야 한다.

다음 큰 항목은 근태 수정과 감사 로그의 원자적 저장, 이미 지급된 근태 수정 정책, 전체 스키마에서의 두 앱 통합 검증이다. 아직 판매 준비 완료로 판정하지 않았다.
