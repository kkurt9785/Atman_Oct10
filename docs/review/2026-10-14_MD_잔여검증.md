# 잇닿 MD 잔여 검증과 수정 결과

2026-10-14 기준. 원본 `2026-10-14_작업검토요청.md`의 A1~C11을 코드와 검증 결과에 연결했다. 재현된 폐쇄 권한 우회, 탈퇴 실패의 성공 표시, 급여 권한 없는 관리자 알림을 로컬에서 수정했다. **항목별 검토는 진행됐지만 전체 출시 검증 완료는 아니다.** 아래 잔여 출시 조건을 충족해야 운영 반영을 판단할 수 있다.

## 사용자가 얻어야 하는 가치

사장님은 누가 일했고 얼마를 지급해야 하는지 빠르게 확인하고, 근무자는 일한 시간과 지급 상태를 신뢰할 수 있어야 한다. 화면에는 현재 할 일과 처리 결과를 먼저 보여 주고, 중복 방지·권한·금액 검증은 내부에서 처리한다. 반복 사용의 가치는 알림 횟수가 아니라 기록의 정확성과 확인에 드는 시간에서 나온다.

처리 결과와 다음 행동을 알려 주는 흐름은 [GOV.UK 완료 안내](https://design-system.service.gov.uk/patterns/confirmation-pages/), 실패 원인과 복구 방법은 [오류 메시지 가이드](https://design-system.service.gov.uk/components/error-message/), 보조기기에도 결과를 전달하는 방식은 [W3C 상태 메시지 기준](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)을 참고했다. 전체 접근성 적합성 인증을 의미하지는 않는다.

## 이번 수정

- `230000` 마이그레이션에 폐쇄·탈퇴·지급 알림 함수 전체 정의를 추가했다. 이미 원격 이력에 있는 `160000`·`170000`은 수정하지 않았다.
- 소유자가 NULL인 사업장을 무관한 로그인 사용자가 닫을 수 있던 조건을 수정했다. 미퇴근 기록 또는 지급 확인되지 않은 완료 단기 근무가 있으면 폐쇄를 거부한다.
- 비활성이라도 아직 닫지 않은 소유 사업장은 탈퇴를 막는다. 근무자 프로필을 유지하는 계정은 푸시 구독과 대기 알림도 보존한다.
- 탈퇴 RPC 응답을 검증하고, 인증 삭제 설정이 없으면 DB 정리 전에 중단한다. 인증 삭제 실패는 완료로 표시하지 않고 세션을 유지해 재시도할 수 있게 한다. DB 정리와 인증 삭제는 여전히 별개 단계다.
- 종료·탈퇴 버튼은 동시 실행을 막고 네트워크 실패를 표시한다. 실패 시 입력과 동의를 유지하며, 관리자 로그아웃은 현재 세션 범위로 제한한다.
- 지급 알림의 위임 관리자 수신자는 급여 열람 권한을 확인한다. 미입금 재알림은 시간대가 아니라 상태 전환을 기준으로 한다. 확인 상태 NULL을 거부하고 직원 → 지급 기록 순서로 잠근다.
- 미적용 `180000`의 지급 불변성 검사에서 근무자 확인 메모를 허용했다. `230000` 입금 확인과 함께 실행하는 회귀 테스트를 추가했다.
- 사업자 조회 저장·목록 조회 실패를 전파한다. 국세청 결과가 없으면 셀프 등록 승인을 보류한다. 배지는 `active` 결과에만 표시하고 “사업자등록 상태 확인”으로 범위를 좁혔다. 키가 없는 환경에서는 승인할 수 없다.
- 주휴 안내를 실제 근무 기록 기반의 참고액으로 바꿨다. 근무자 정산 조회는 월과 주의 전체 범위를 포함하고 월 합계는 해당 월로 한정한다. 근태 조회 중이거나 실패한 경우 합계 대신 상태를 표시한다. 예정 휴게를 자동 차감으로 오해시키는 문구도 수정했다.
- 일용근로소득의 15만원을 비과세 한도가 아닌 공제액으로 안내한다. 기존 데모 복구 스크립트가 삭제형 크론을 되살리는 문제는 `DEMO_GUIDE.md`에 실행 금지와 새 정책으로 명시했다.
- 추가 반영: 최저시급을 공통 모듈로 묶어 근무 연도 기준으로 검사한다. 2026·2027, 다년 고정 시급, 연말 야간 공고·프로젝트를 처리하며 미등록 연도는 이전 금액으로 통과시키지 않는다. 공고·프로젝트·직원 급여·결원·반복 일정의 서버 검사를 바꾸고, `20261015000000`에 직접 DB 쓰기 검사를 추가했다. 기존 지급 금액은 변경하지 않는다.
- 시급 입력은 1원 단위로 통일했다. 10,320원 하한에 100원 단위를 조합해 15,000원 같은 정상 금액까지 브라우저가 거부할 수 있던 문제를 제거했다.
- 정산의 계좌·근무지·지급 조회 실패를 빈 데이터와 구분하고 다시 불러오기를 제공한다. 월·주 집계를 공통 함수로 검증하고 지급일은 한국 시각으로 판단한다. “받은 금액”은 “지급 완료 기록”으로 바꿔 실제 입금 확인과 구별한다. 조회 상한에 닿으면 일부 합계를 전체로 보여 주지 않는다.

## 검증 근거

- 근무자 Vitest: 19개 파일, **141개 테스트 통과**. 관리자 탈퇴·사업자 승인, 연도별 시급 13건, 월·주 경계 3건도 포함된다.
- 두 앱 프로덕션 빌드 통과. 관리자 사업자 승인 보류 변경 이후 최종 빌드와 근무자 추가 테스트의 타입 검사도 통과했다.
- `scripts/qa-md-remaining-sql.mjs`: 로컬 PostgreSQL의 격리 스키마에서 실제 마이그레이션 함수 정의를 실행한다. 무관한 authenticated 사용자 권한 거부, 열린 근태·완료 미정산 차단, 정상 폐쇄·반복 호출·지급 이력 보존, 알림 권한·중복, 근무자 구독 보존을 검증하고 전부 롤백했다. 전체 운영 스키마 재생이나 다중 세션 테스트는 아니다.
- `scripts/qa-account-closure-ui.mjs`: 360·390px 실제 React 컴포넌트의 중복 클릭, 상충 작업 차단, 실패 후 재시도, 입력 보존, 데모 버튼 비노출, 화면 넘침·버튼 높이를 확인했다. 백엔드는 모의 서비스다.
- `scripts/qa-admin-payout-ui.mjs`: 같은 두 폭에서 18개 지급 UI 회귀 검사 통과. 실제 지급·탈퇴·푸시 발송은 수행하지 않았다.
- 정산 월·주 경계와 한국 시각 지급일은 공통 집계 함수 회귀를 통과했다. 실데이터로 이전 달과 다음 달을 넘기는 화면 시나리오는 추가 검증 대상이다.
- `qa-minimum-wage-sql.mjs`: 새 최저시급 마이그레이션 전체를 격리 스키마에 적용해 직접 쓰기, 연말 야간, 연도·기간 변경, 취소 후 재활성화, 미등록 연도 거부, 과거 금액 보존을 검증하고 롤백했다. `qa-minimum-wage-ui.mjs`는 실제 프로젝트 폼의 10,320·15,000원 입력, 2027 하한, 다년 기간, 미등록 연도 안내를 확인했다.
- 초기 `characterization` 테스트는 결함을 재현하는 테스트였으며, 현재 같은 이름의 파일들은 수정된 기대 동작을 검사하도록 바꿨다. 초기 통과를 수정 완료 근거로 쓰지 않는다.

## 운영 반영 상태

읽기 전용 `supabase migration list --linked` 결과에서 `120000~170000`은 원격 이력에 있었다. 원본의 “130000~170000 미반영” 문장은 현재 이력과 다르다. 이력만으로 실제 함수 본문이 로컬과 같다는 뜻은 아니다.

`180000~220000`은 원격 미적용이었고, 이번 `230000` 및 `20261015000000`도 로컬 추가 상태다. 운영 DB 쓰기·배포·사용자 삭제·실제 알림 발송은 하지 않았다. `180000`의 확인 메모 허용 변경은 이 미적용 확인을 전제로 한다.

## 법과 세무 안내의 범위

일용근로소득에는 일 15만원 공제가 적용되며, 공제 후 세율·세액공제·소액부징수 규칙이 따른다. 단기 계약이라는 이름만으로 모두 일용근로소득이 되는 것은 아니다. [국세청 일용근로소득 안내](https://mob.tbwe.hometax.go.kr/jsonAction.do?actionId=UTBICAAA01F001)

주휴수당 판단에는 실제 기록 외에 4주 평균 주 소정근로시간과 소정근로일 개근 등의 조건이 필요하다. 현재 참고액은 이 조건을 판정하지 않는다. [고용노동부 상담 안내](https://1350.moel.go.kr/rtmview.do?id=1000261283)

최저임금은 근무 연도에 맞춰 적용해야 한다. 공통 규칙은 2026년 10,320원과 2027년 10,700원을 사용한다. 기간 전체에 고정 시급 하나를 지정하면 포함된 연도 중 높은 기준을 적용하는 보수적 제품 정책이다. [고용노동부 2027 최저임금 확정 안내](https://www.moel.go.kr/news/enews/report/enewsView.do?news_seq=19744)

국세청 사업자등록 상태조회만으로 구인자의 신원·대표 권한이나 직업정보 제공의 법적 요건 전체를 충족한다고 볼 수 없다. 2026-12-10 시행 개정에 맞춰 신원·허위광고 검증 및 필요한 공개 정보 제공을 검토해야 한다. [직업안정법 개정문](https://law.go.kr/LSW/lsRvsDocListP.do?chrClsCd=010202&lsId=001765&lsRvsGubun=all)

근로 관계 기록의 보존 의무와 서비스 탈퇴는 구분해야 한다. 폐쇄 시 soft delete하는 것만으로 보존·접근 통제·반출·기간 만료 파기까지 완성되는 것은 아니다. [근로기준법 기록 보존](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1029728189). 운영 정책은 노무·세무·개인정보 담당자의 확인이 필요하다.
