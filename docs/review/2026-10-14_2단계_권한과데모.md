# 2단계 — 지급·계좌 권한 및 데모 준비

2026-10-14. 시작 시 사용자가 확인한 잔여량 96%. 단계 완료 후 사용량을 확인한다. 운영 적용 전 로컬 구현·검증 결과이며 제품 전체 출시 승인은 아니다.

## 수정한 문제

- `can_view_payroll=false`인 위임 관리자도 직접 DB 조회로 지급 내역을 읽을 수 있었다. 긱 지급·직원 급여·의료 근무 지급·계좌 공유 메타데이터의 관리자 RLS를 공통 급여 권한 함수에 연결했다. 기존 근무자 자신의 지급 조회 정책은 유지한다.
- 전체 계좌를 복호화하는 `get_gig_shared_bank_accounts`도 급여 권한을 검증한다. 과거의 잘못된 시연/실계정 연결에 속한 계좌는 조회 결과에서 제외한다.
- `facility_access_role`은 비활성·닫힌 사업장과 시연/실계정이 교차하는 관리자 권한을 거부한다. 앱의 관리자 컨텍스트도 사용자 JWT로 이 함수를 호출한다. 기존 서비스 키 조회에서 위임 관리자에게 빠졌던 활성 사업장 조건을 DB와 일치시켰다.
- `facility_staff` 연결과 계좌 공유에 DB 트리거를 추가하여 초대 함수 외의 쓰기 경로에서도 실제 근무자 ↔ 시연 사업장, 시연 근무자 ↔ 실제 사업장 연결을 거부한다.
- 플랫폼 관리자 ID 허용 목록에 시연 계정이 들어갔을 때 이메일 차단을 우회하던 경로를 수정했다.
- 사업장 시연 여부 확인 실패 시 민감 작업을 허용하던 가드를 차단 방식으로 수정했다. 직원 급여 기준 변경 액션에도 급여 관리 권한을 적용했다.

## 데모 근무자 주기 준비

사용자 추가 요청: 데모 근무자를 적절한 시간 단위로 활성화해 시연 가능하게 유지한다.

- DB 크론 `demo-worker-readiness-15min`: 15분마다 실행하도록 마이그레이션에 등록한다. 로그인 때도 같은 준비 함수를 실행한다.
- 승인 상태인 시연 근무자의 활동 시간을 갱신한다. 실제 근무자·탈퇴 근무자·차단된 인증 계정은 갱신하지 않는다. 면허 승인·위치 변경·삭제된 계정 복구를 하지 않는다.
- 지정된 병원·약국·요양병원의 기존 시연 공고 중, 시작 시간이 지나거나 한 시간보다 먼 미시작 공고를 다음 15분 경계부터 45분 시연 구간으로 옮긴다. 금액도 45분 기준으로 맞춘다. 실제 지원자가 섞인 공고·근태가 있는 공고·진행 중/완료 근무는 제외한다.
- 초대 근무 고정 시연자는 근태가 없을 때 현재부터 45분으로 맞춘다. 기존 기본 일정 동기화 트리거가 호환 배정에 전파한다. 오늘의 근태 또는 이전 날짜의 미퇴근 기록이 있으면 변경하지 않는다.
- 초대 근무 재로그인은 최근 세션·미퇴근 근무·최근 한 시간 내 완료 기록을 유지하고 `/gig`로 이어진다. 한 시간 이상 지난 완료/유휴 세션은 다음 로그인 시 기존 데모 전용 초기화 함수를 사용한다. 기존 초기화의 삭제 대상은 데모 데이터이며 이번 로컬 검증에서는 실제 초기화를 실행하지 않았다.
- 운영 전환 스크립트의 크론 해제 대상에 새 작업을 추가했다.

## 검증

- TypeScript 검사 통과.
- 관리자·근무자 프로덕션 빌드 모두 통과.
- Vitest 총 34개 통과: 이전 29개 + 플랫폼 관리자 시연 우회 2개 + 데모 이어하기/준비 실패 동선 3개.
- PostgreSQL 실제 `authenticated` 역할과 `auth.uid()`를 사용한 RLS/RPC 테스트 통과: 소유자, 급여 비허용 관리자, 급여 허용 관리자, 외부 계정, 잘못된 실사업장 권한이 있는 데모 계정, 닫힌 사업장, 실제 계좌의 데모 노출 방지, 근무자 자신의 지급 조회.
- 별도 스키마에서 데모 주기 함수 테스트 통과: 대상 제한, 활동 갱신, 미시작 시간 조정, 실제/탈퇴/차단 계정 제외, 실제 사용자의 준비 RPC 거부, 진행 중 근무 보존, 재로그인 이어하기, 오래된 완료 세션 초기화 분기.
- DB 테스트는 각각 전체 트랜잭션을 롤백했다. 기존 로컬 테이블과 운영 DB를 수정하지 않았다. 데모 테스트의 초기화 구현은 호출 여부만 기록하는 대역이며, 기존 초기화 함수의 전체 삭제·재시드 통합 검증은 별도다.

## 적용 및 다음 검증

- 새 마이그레이션: `20261014190000_payroll_access_and_demo_boundaries.sql`, `20261014200000_demo_worker_readiness.sql`. 1단계 마이그레이션과 앞선 미반영 변경까지 순서대로 검증 후 배포해야 한다. 지금은 운영 적용·커밋·푸시를 하지 않았다.
- 실제 브라우저에서 두 기기로 로그인→초대/지원→출퇴근→지급을 검증해야 한다. 새 cron은 운영 반영 후에만 실제로 실행된다.
- 기존 하루 단위 전체 시드 작업은 그대로 남아 있다. 새 15분 작업 자체는 삭제하지 않지만, 기존 전체 초기화와 장시간 시연의 충돌을 피하려면 활성 세션을 감지해 전체 시드를 연기하는 후속 조정이 필요하다.
- 이번 권한 보강은 지급 테이블·계좌 RPC·관리자 컨텍스트에 적용했다. `facility_staff.pay_rate`, `gig_assignments` 등 운영 화면에서 사용하는 급여 기준 필드의 관리자별 최소 노출은 추가 점검 대상이다. 모든 급여 관련 필드의 비노출을 완료했다고 판단하지 않는다.
- 과거에 이미 잘못 연결된 시연/실계정 행은 자동 삭제·재연결하지 않았다. 운영 데이터 대조가 필요하다.
- 데모 주기 작업은 기존 시드 공고를 유지하는 방식이다. 시드 자체가 없거나 모든 공고가 완료된 경우의 새 시나리오 생성, 예약 크론 중단/오류 시 운영 경고는 후속 통합 검증 대상이다.

다음 우선순위: 브라우저에서 사용자 동선을 확인하며 데모의 일일 초기화 충돌과 근태→지급 전환을 정리하고, 그 뒤 모바일 UI/UX를 점검한다.
