# 3단계 — 출퇴근 복구 동선·위치 동의·시연 시간

시작 사용량: 사용자 확인 94%. 작업 범위를 한 단계로 제한했다. 운영 배포·운영 DB 변경·실제 출퇴근 기록 생성은 하지 않았다.

## 반영한 사항

- 긱 홈의 DB 조회 실패를 ‘연결된 근무 없음’으로 보여 주지 않고 별도 오류·재시도 화면으로 처리한다. 근태·인증 설정을 조회하지 못한 상태에서는 출퇴근 버튼을 열지 않는다.
- 전날 출근한 미퇴근 기록이 오늘 예정 기록보다 먼저 표시된다. 일정 표시도 선택된 근태의 근무일을 따른다.
- 출퇴근 처리 중 예외가 발생해도 버튼 잠금을 해제한다. 상태 렌더링 전 연속 입력은 ref 잠금으로 차단한다. 키 반복 입력을 무시하고 보조기기의 click 활성화를 지원한다.
- 시간·배정·중복 기록 오류에는 해결책이 아닌 QR 재인증을 제안하지 않는다. 긱 워커는 해당 근무지의 사장님 대화로 이동해 확인을 요청할 수 있다. 자동 메시지를 보내지는 않는다.
- 출근→퇴근 버튼 교체 후에도 저장 완료·지각 안내가 남는다. 안내를 페이지 상단으로 옮겼다. 흰 배경에 어두운 테마용 흐린 안내가 표시되던 부분도 수정했다.
- 위치 동의 조회 오류·기록 없음은 위치 사용 허용으로 처리하지 않는다. 계정 전환이나 다른 기기의 철회를 놓치는 영구 캐시를 제거했다. 개인정보 설정의 조회 실패도 동의 켜짐으로 표시하지 않는다.
- 관리자 근태 내역의 다음 동선은 사업장 모드에 따라 긱 지급 `/gig-pay` 또는 의료 급여 `/payroll`로 연결한다.
- 근태 수정에서 마감 상태 조회 오류 시 중단하고, 출근일이 근무일과 달라지거나 휴게가 실제 체류시간을 초과하는 입력을 차단한다. 수정 후 긱 지급·홈 집계도 갱신한다.
- 현장 시연 준비는 과거 15분 전이 아니라 **다음 15분 경계 시작·45분 근무**로 만든다. 이미 시작한 공고의 지원을 차단하는 규칙과 충돌하지 않는다. 자정·연말 날짜 이동을 처리하며 생성 컬럼 `is_overnight`를 직접 수정하지 않는다. 예상 지급액도 45분으로 맞춘다. 실제 출퇴근은 기존 서버의 시간·인증·승인 규칙을 그대로 따른다.

## 검증

- Vitest 53개 통과: 기존 34개 + 동의 확인 4개 + 출퇴근 오류 분류·야간 기록 선택·시연 시간 경계 15개.
- 두 앱 TypeScript 검사 및 배포용 빌드 통과.
- Chrome 모바일 360px·390px에서 실제 배포용 워커 빌드를 실행했다. `scripts/qa-worker-attendance.mjs`는 가짜 로그인 세션과 모의 DB 응답만 사용한다. 외부 출퇴근·알림·데모 초기화 요청은 전송하지 않는다.
- 각 화면 폭에서 조회 실패와 재시도, 시간 오류와 사장님 대화 링크, 잘못된 QR 제안 없음, 네트워크 실패 후 재시도, 같은 프레임의 중복 click 차단, 버튼 교체 후 성공 안내 유지, 가로 넘침 없음, 미처리 브라우저 오류 없음을 확인했다.
- 스크린샷을 직접 확인해 저장 안내 위치를 추가 조정했다.

브라우저 검사 실행법: 워커 앱에서 `npm run build`, `npm run start -- --hostname 127.0.0.1` 후 루트에서 `node scripts/qa-worker-attendance.mjs /absolute/path/to/playwright-core`. 로컬 Chrome과 별도 Playwright 설치가 필요하다. 테스트는 운영 인증·DB 통합 검증을 대체하지 않는다.

## 다음 단계의 큰 위험

1. 기존 일일 데모 전체 재시드 작업은 2단계의 15분 준비 작업과 별개다. 활성 시연 세션에 대한 갱신 유예/잠금이 아직 없어 진행 중 데이터를 초기화할 수 있다. 기존 SQL cron과 서버 재시드를 함께 제어해야 한다. 현장 시연의 수동 reset도 현재 파괴적 의미를 유지한다.
2. 근태 수정과 감사 로그 기록이 별도 요청이다. 원자적 RPC와 마감·수정·지급의 동시성 보호가 필요하다. 이미 지급된 기록의 수정·차액 정산 정책도 아직 해결되지 않았다.
3. 로컬 DB가 최신 전체 스키마가 아니므로 실제 계정의 초대→출퇴근→지급 전 과정은 아직 통합 검증하지 못했다. 배포 전 호환 스키마의 격리 환경에서 확인해야 한다.
4. 동의 기록이 없는 기존 계정은 위치를 쓰기 전에 내 정보에서 명시적으로 동의해야 한다. 이 변경은 의도된 안전 기본값이다. GPS만 가능한 사업장의 기존 계정 전환 안내가 필요하다.

판매 준비 완료 판정은 아직 하지 않았다. 운영 반영 전 남은 위험과 배포 순서를 별도로 확인한다.
