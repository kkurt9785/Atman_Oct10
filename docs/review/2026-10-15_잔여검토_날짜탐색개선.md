# 잇닿 잔여 검토·날짜 및 탐색 개선

## 반영 완료

- 탈퇴 승인과 파일 삭제 예약을 같은 DB 트랜잭션으로 처리. 탈퇴 거절·계정 삭제 실패 시 사진을 먼저 삭제하지 않는다. 서버 파일 삭제는 5분 주기·실패 재시도 방식.
- 채팅·워크룸 신고/차단, 차단 목록·해제, 서버 메시지 접근 제한 및 채팅 알림 차단. 근태·급여 시스템 기록과 알림은 유지.
- 플랫폼 운영자만 신고를 검토하고 위반 메시지를 안내 문구로 대체. 원문·처리 담당·결과는 신고 기록에 1년 보관. 24시간 미처리 신고와 파일 정리 지연을 운영 점검에 포함.
- 채팅·워크룸 최신 100개와 이전 대화 더 보기. 조회 실패와 빈 목록 구분, 전송 중복 방지·실패 시 초안 보존·대화방별 초안 분리.
- 관리자 공개 개인정보 안내, 두 앱 차단 관리 링크, 공통 오류/없는 페이지 복귀 경로와 모바일 키보드 영역 대응.
- 사장님 단기 등록: **하루 / 연속 며칠 / 요일 반복**. 연속 19~21일은 주말 포함 3일. 서버에서 실제 날짜·기간·요일을 검증하며 기존 계약/요일 DB 모델과 근태 연결을 유지.
- 기간 달력: 시작일·종료일 개별 수정, 종료일 재선택 시 전체 초기화 방지, 역순 클릭 시 양 끝 날짜 보존, 같은 날·월/연도 경계 선택.
- 워커 홈의 기본 지역을 첫 지역 한 곳에서 설정 지역 전체로 변경. 처음부터 임의의 날짜·시간대 하나를 선택하지 않고 이번 주 전체를 표시.
- 근무 찾기: 두 지역 합산/개별 선택, 직접 날짜 범위, 오늘/앞으로 7일, 시간대 필터, 날짜·시간/거리/시급 정렬. 실제 정렬과 불일치하던 추천 문구 제거. 거리 값은 직선거리로 표시하고 근거 없는 이동 시간 추정을 제거.
- 활동 지역 조회 실패 시 기본값으로 덮어쓰지 않고 재시도 제공. 저장 중 중복 요청 방지.
- 기존 매일 08:30 시연 재시드와 15분 준비 정책 유지. 이전 정책을 기대하던 테스트만 현행 정책으로 정정.

## 워커 근무표 재검토: 제안, 아직 미적용

운영 화면의 7일×3시간대 표는 확정·지원·공고 수를 ●/○/+N으로 합쳐 보여준다. 확정 칸을 눌러도 아래는 공고 목록이어서 실제 근무 상세와 연결되지 않으며, 전체 보기에는 23개 공고가 긴 목록으로 나타났다. 날짜·지역 필터 수정만으로 첫 화면의 목적 혼합은 해결되지 않는다.

추천 구조:

1. **홈:** 출근/퇴근 등 지금 할 일 → 다음 확정 근무 카드(날짜·시간·사업장·상태) → 지원 결과 대기 요약 → 새 근무 찾기. 추천을 넣더라도 2~3개로 제한.
2. **내 근무:** 날짜순 일정 카드를 기본으로 확정/대기/완료를 글자로 구분. 달력은 선택 가능한 보조 보기. 확정 일정을 누르면 실제 해당 근무 상세로 이동.
3. **근무 찾기:** 저장한 두 지역을 합쳐 조회, 가능한 날짜·시간을 선택, 날짜/거리/시급 정렬. 모든 사람에게 날짜순이 최적이라고 단정하지 않는다.
4. 의료인에게 익숙한 D/E/N 표는 필요한 사용자가 선택하는 보기로 유지할 수 있으나 약국·단기 근로자의 공통 기본 화면으로 강제하지 않는다.
5. 기존 인력은 본인의 예정 근무·출퇴근을 먼저, 아직 확정 근무가 없는 사람은 근무 찾기를 먼저 보여준다. 구현 시 공고 지원 내역뿐 아니라 사업장 직원 계약·일정도 함께 검증해야 한다.
