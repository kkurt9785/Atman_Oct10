# 잇닿 Google Play 제출 전 최종 검토

2026-10-14 · 범위: 관리자·근무자 웹앱, 의존성, 로그인·탈퇴, 채팅, 결제, 제출 요건.

**판정: 웹앱 보안·접근 경로는 개선했으나, Google Play 제출 준비 완료는 아니다.** 아래 미해결·미확인 항목을 닫은 뒤 실제 AAB로 검증해야 한다. 조직 계정도 앱 심사는 별도로 받는다.

## 이번에 수정·검증한 내용

- 두 앱 Next.js 15.5.23 → 15.5.27, sharp 0.35.0 → 0.35.5, source-map-js 1.2.2 고정. 운영 의존성 `npm audit --omit=dev`: 각각 3건 → 0건.
- 긱워커가 `/settings/withdraw`에서 홈으로 튕기던 의료 셸 가드 수정. 공통 계정 삭제 화면에 의료 전용 하단 메뉴를 붙이지 않는다.
- 공개 삭제 안내 `/account-deletion` 추가. 브라우저에서 로그인 → 삭제 화면으로 이동하며 가입 미완료 계정도 삭제 화면을 열 수 있다. 개인정보 처리방침에서 연결한다.
- 로그인 후 이동 주소는 같은 사이트의 안전한 경로만 허용. 토큰 교환 실패를 가입 화면으로 보내지 않고 실패로 표시한다. 가입이 필요한 초대 경로는 가입 완료까지 보존한다.
- 두 앱 로컬 프로덕션 빌드 통과. 근무자 Vitest 157개, 임금 엔진 19개 시나리오 통과.
- 브라우저 번들 150개에서 로컬에 설정된 서버 비밀값 3개와 service-role JWT를 검사해 노출을 찾지 못했다. 모든 운영 환경변수의 완전한 검증을 뜻하지 않는다.
- 개발·빌드 도구 전체 감사에는 관리자 9건(Moderate 3 / High 6), 근무자 12건(Moderate 4 / High 6 / Critical 2)이 남는다. Tailwind·Vitest 계열로 운영 의존성과 구분하며, 강제 메이저 업데이트는 하지 않았다.
- 이번 보안·경로 변경은 두 운영 웹앱에 배포 완료(`READY`). 관리자 로그인·삭제 안내·개인정보 페이지 HTTP 200, 개인정보 문서의 삭제 페이지 링크, 비인가 크론 HTTP 401을 확인했다. 실제 삭제 클릭·기기 설치 검증은 아니다.

## 제출 전에 해결할 항목

| 우선순위 | 발견 사항·근거 | 완료 조건 |

| P0 | 1:1 채팅·워크룸에서 신고·사용자 차단 UI와 이를 강제하는 DB/RPC를 찾지 못했다. | 신고 접수·운영자 처리와 서버에서 동작하는 차단. 기존 근무·근태 기록 접근과 채팅 차단을 구분해야 한다. |
| P0(관리자 앱) | 유료 업무 기능·공고 추가 구매에 Toss 결제 흐름을 사용한다. Play Billing 또는 허용된 대체결제 프로그램 연동은 확인되지 않았다. | Play 배포 앱의 디지털 기능 결제 방식 확정·연동. 근로자 임금 지급과 앱 이용료 결제를 구분한다. 웹 결제가 작동한다는 것만으로 Play 요건을 충족하지 않는다. |
| P0(관리자 앱) | 관리자 앱에서 개인정보 처리방침 링크를 찾지 못했다. 현재 근무자 처리방침은 근무자 가입·면허·계좌 중심으로 작성되어 있다. | 관리자 로그인·설정에서 접근 가능한 공개 처리방침 연결, 사업자 서류·직원 관리·관리자 정보의 실제 처리 범위 반영, Play 등록 정보와 일치 확인. |
| 미확인 | 현재 저장소에 Android 프로젝트·AAB·APK·서명·Digital Asset Links 설정이 없다. 두 운영 도메인의 `/.well-known/assetlinks.json`도 HTTP 404다. 별도 패키지 존재 여부는 확인하지 못했다. | 패키징 방식과 실제 AAB 확보, 패키지명·서명·버전·targetSdk 확인. 현재 신규 제출 기준은 API 36 이상. TWA 방식이면 실제 Play 서명 인증서로 도메인 연결 검증. |
| 미확인 | Play Console 조직 인증·Data safety·등급·앱 액세스 안내와 실제 Android 권한/SDK 목록은 열람하지 않았다. | D-U-N-S 등 조직 인증 완료, 개인정보 URL·삭제 URL 등록, 데이터 수집·공유 선언과 패키지 동작 대조, 심사 계정·QR·위치 제약 안내 준비. |
| 미검증 | 실제 Android 설치 상태에서 카카오 로그인 복귀, 뒤로가기, 카메라·위치 권한 거부, 푸시 수신·탭 이동, 네트워크 끊김, 출퇴근→지급 확인 전체 흐름. | 내부 테스트 트랙의 AAB를 실제 기기에 설치해 역할별 검증. 웹 빌드·모의 테스트 통과와 별도다. |

## 제출 정보에 사용할 주소

- 근무자 앱: https://itdot.co.kr
- 관리자 앱: https://admin.itdot.co.kr
- 개인정보 처리방침: https://itdot.co.kr/legal/privacy
- 계정 삭제 안내: https://itdot.co.kr/account-deletion

## 공식 근거

- [신규 개인 계정 테스트 요건](https://support.google.com/googleplay/android-developer/answer/14151465): 해당 신규 개인 계정에 12명·14일 연속 비공개 테스트 요건. 조직 계정도 앱 심사는 별도다.
- [계정 등록 요건](https://support.google.com/googleplay/android-developer/answer/10788890): 조직 정보·D-U-N-S·심사 접근 정보 등.
- [현재 target API 요건](https://support.google.com/googleplay/android-developer/answer/11926878): 2026-08-31부터 신규 앱·업데이트 API 36 이상.
- [계정 삭제 요건](https://support.google.com/googleplay/android-developer/answer/13327111): 앱 내 경로와 앱 외 웹 요청 경로, 보관 데이터 안내.
- [사용자 생성 콘텐츠](https://support.google.com/googleplay/android-developer/answer/9876937): 신고와 1:1 상호작용의 차단 기능.
- [결제 정책](https://support.google.com/googleplay/android-developer/answer/9858738): 디지털 기능·업무용 소프트웨어 결제 및 대체결제 프로그램 조건.
- [TWA 도메인 연결](https://developer.chrome.com/docs/android/trusted-web-activity/quick-start): 서명과 Digital Asset Links 검증.

운영 데이터 삭제, 실제 사용자 탈퇴, 실결제, 실제 알림 발송, Play Console 제출은 이번 검토에서 수행하지 않았다.
