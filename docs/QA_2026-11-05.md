# QA 2026-11-05 — 단기 근무 지급: 정산 기간 끝 + 한 번에 지급 기록

단기근로 점검(`docs/QA_2026-10-14_단기근로.md`) 기능 6 "기간 선택·전원 지급 + 지급 전 미완료 경고"를 /gig-pay 에 넣었다. Spendly 영수증 출력의 기간 선택·일괄 처리 동선을 참고했다. DB 변경 없음.

## 바뀐 것

| 항목 | 내용 |
|---|---|
| 정산 기간 끝 | /gig-pay 위 '정산 기간' 칸. 오늘까지(기본)·어제까지·지난주까지(월~일 기준, 일요일엔 그 전 주) 칩 + 날짜 직접 고르기. 주소 `?until=YYYY-MM-DD` 로 서버가 근무자별 금액을 다시 계산. 검색·페이지 이동에도 유지 |
| 한 번에 지급 기록 | 지급할 수 있는 근무자가 2명 이상이면 표시(검색으로 좁혔을 땐 숨김). 이름별 실지급·세전/공제/실지급 합계, 3.3% 일괄 적용 스위치(모두 프리랜서일 때만), '모두 이체 완료 기록'은 한 번 더 확인, '모두 나중에 지급'은 날짜·메모 |
| 경고·제외 | 퇴근 전 근무가 있는 사람 이름 경고(그 근무는 이번 지급에 안 들어감). 빠지는 근무자와 사유(계좌 전달 대기·급여 기준 미설정·월급·0원)를 접어서 표시 |
| 서버 | `createGigPayoutsBulkAction`: 근무자마다 한 명 기록과 같은 `recordGigPayout`(사업장 소속·긱 근무자·계좌·급여 기준·근태 재계산·화면 금액 일치)을 순서대로 실행, 실패해도 나머지는 기록하고 사람별 결과 반환, 알림 깨우기 1회. 한 명 기록도 `until` 을 받음. 끝 날짜가 오늘 이후·없는 날짜면 거절 |
| 안전 | 이전 지급분은 근태 ID로 빠지므로 끝 날짜 뒤 근무는 다음 지급에 그대로 남음. 화면에 보이던 끝 날짜를 그대로 보내 자정을 넘겨 눌러도 같은 기준으로 계산 |

## 검증

- `node scripts/qa-gig-pay-period.mjs` — 순수 함수 27개 PASS(지난주 일요일·KST 자정·없는 날짜 2026-02-30 거절·대상 판정). 이 점검이 '없는 날짜를 3월로 넘겨 받는' 버그를 잡아 고쳤다.
- `node scripts/qa-admin-bulk-payout-ui.mjs <playwright-core>` — 360·390px 각 12항목 PASS(기간 칩·경고·합계와 3.3%·제외 사유·완료 전 재확인·한 번만 전송·사람별 부분 실패·목록이 새로 그려져도 결과 유지·예정일과 메모·검색 시 일괄 숨김·직접 고른 날짜·가로 넘침 없음). 실제 백엔드 쓰기 0.
- 기존 `qa-admin-payout-ui.mjs`(근무자별 지급 칸) 360·390px PASS, admin-web `tsc --noEmit`·`next build` 통과.
- **안 한 것**: 운영 DB에서 실제 일괄 기록은 실행하지 않음(시연 사업장 포함). 배포 후 시연 사업장에서 화면 표시만 확인.
