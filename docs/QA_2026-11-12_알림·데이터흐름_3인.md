# 알림·데이터 흐름 QA 3인 (2026-11-12)

읽기 전용 QA 3명을 병렬로 돌렸다. 운영 DB에는 아무것도 쓰지 않았다.

1. **알림 표 전수**: 코드와 마이그레이션을 읽었다.
2. **관리자↔근무자 데이터 흐름 추적**: 코드와 마이그레이션을 읽었다.
3. **운영 시연 화면 간 숫자 비교**: Playwright로 시연에 로그인해 화면만 열었다. REST 쓰기 요청은 막았고, `/gig/demo`는 열지 않았다.

함께 레포의 격리 SQL QA 9개를 pglite(메모리 Postgres)로 돌렸다. 8개는 통과했다. `qa-gig-sites-sql`은 PostGIS가 없어서 돌리지 못했다.

> 주의: 운영 시연에 쓰는 `server_qa_demo1.py`·`qa-workroom-operational.mjs`·`qa-realtime-rls.mjs` 같은 쓰기 QA는 이번에 돌리지 않았다. 9월에 시연 대화방에 [QA] 흔적을 남긴 스크립트들이다. 영업 직전이라 시연 데이터를 바꾸지 않으려고 뺐다.

### B. 알림 — ✅ 처리

| 항목 | 처리 |
|---|---|
| **P0** 로그아웃하거나 관리자 시연을 끝내도 그 폰으로 이전 계정 알림이 갔다. 발송기는 계정에 묶인 구독 전부로 보낸다 | 로그아웃·시연 종료 때 이 기기 구독을 지운다(두 앱의 `forgetThisDevicePush`). DB 트리거로 한 기기(endpoint)에는 마지막으로 알림을 켠 계정 하나만 남긴다. 이미 겹친 구독도 정리했다 |
| 연차 신청 알림을 누르면 홈이 열렸다 | 알림을 눌렀을 때 열 수 있는 화면 목록에 `leave`·`gig-work`·`more`·`setup`·`ops`를 더했다. 등록 반려(`/setup`)는 지워진 사업장으로 전환하지 않는다 |
| '대화 2'를 보고 들어가도 어디에 새 메시지가 있는지 안 보였다. 읽어도 숫자가 바로 안 줄었다 | 사람 칩에 안 읽은 수를 표시한다. 전체 공지방에 새 글이 없으면 안 읽은 1:1 대화부터 연다. 읽음이 저장된 뒤 하단 탭 숫자를 다시 받는다. 열어 둔 대화에 온 메시지는 바로 읽음 처리한다. 근무 종료·연결 해제된 사람의 대화는 숫자에서 뺀다 |
| 단기 전용 근무자가 대화방·출석 확인 푸시를 누르면 '오늘' 화면이 열렸다 | 셸 가드가 `/workroom`은 `/gig/workroom`으로, `/notifications`는 `/gig/notifications`로 옮긴다 |
| 알림 문구 | '휴가가 승인됐어요'·'휴가 신청이 들어왔어요' → 종류 이름(연차·오전 반차·병가…)으로 바꿨다. '💬 병원에서 메시지' → '사업장에서', '워커에게 메시지가 왔어요' → '근무자 메시지가 왔어요'. 알림 함수 5개의 이름 대체값 '워커'·'근로자' → '근무자'(새 지원 알림은 '지원자'). 해요체 2곳을 고쳤고, 이미 쌓인 채팅 안내문도 맞췄다 |
| 새 지원 알림에 사업장 정보가 없어, 사업장이 여럿인 관리자의 다른 사업장 알림함에도 섞였다 | `shift.applied` 알림에 `facilityId`를 넣고, 이미 쌓인 알림도 채웠다 |

검증:
- pglite에서 실제 운영 함수 정의로 마이그레이션 3개(130000·140000·150000)를 이어서 돌렸다. 약사 시연 계정에 로그인 계정이 있을 때와 없을 때 두 경우 모두 통과했다.
- 단위 테스트는 6개를 더해 모두 494개이고 전부 통과했다. 두 앱 타입 검사도 통과했다.
