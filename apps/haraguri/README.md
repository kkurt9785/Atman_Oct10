# HARAGURI

최근 전체 점검·가계부 사용법·월급일 및 자산 관리 결정사항: [2026-11-02 검토](REVIEW_2026-11-02.md).

가계부는 지출·수입·자금 이동을 구분합니다. 본인 계좌 간 이동은 기록을 남기며 지출·수입·예산·카드 실적·정산에서 제외합니다. 앱 내부 포인트 적립은 지출로 수집하지 않습니다. 자동 수집 단축어는 알림의 제목과 본문을 모두 전달해야 하며, 실제 결제 저장과 계정 연결 성공을 구분합니다.

잇닿 Git 저장소 안의 독립 Next.js 가족 PWA. 기존 `admin-web`, `worker-web`의 화면·인증 저장소·DB 마이그레이션과 분리했습니다.

## 실행

```sh
cd apps/haraguri
npm install
cp .env.local.example .env.local
npm run dev
```

배포 주소: https://haraguri.vercel.app

로컬 주소: http://localhost:3004

환경변수가 없으면 로그인 대신 **로그인 없이 미리보기**로 사용할 수 있습니다. 샘플 데이터 및 미리보기 수정은 메모리에만 보관하고 새로고침하면 초기화됩니다. 실제 계정의 데이터와 혼합하지 않습니다.

## Supabase 연결

현재 별도 `HARAGURI` 조직의 서울 리전 프로젝트 `rwyvqxkweqsoositvlht`에 연결되어 있습니다. 기존 잇닿 프로젝트는 변경하지 않았습니다.

- 대시보드: https://supabase.com/dashboard/project/rwyvqxkweqsoositvlht
- API: https://rwyvqxkweqsoositvlht.supabase.co
- 로컬 로그인 복귀 주소: `http://localhost:3004`, `http://127.0.0.1:3004`
- `.env.local`에는 공개 키만 저장. DB 비밀번호·검증용 관리자 키는 Git 제외 `.env.supabase-admin`에 분리

다른 환경에서 다시 연결하려면 아래 절차를 사용합니다.

1. 선택한 프로젝트에 `supabase/migrations/`의 마이그레이션을 순서대로 적용합니다. 기존 루트 `supabase/migrations` 자동 적용 경로와 분리되어 있습니다.
2. `.env.local`에 해당 프로젝트 URL과 공개 publishable/anon 키를 입력합니다. 서비스 역할 키를 프론트에 넣지 않습니다.
3. Supabase Auth의 이메일 로그인을 활성화합니다. Site URL 및 Redirect URLs에 개발 주소와 실제 배포 주소를 등록합니다.
4. 이메일 링크 또는 메일에 표시된 인증번호로 로그인합니다. 실제 메일 발송은 Supabase Auth/SMTP 설정이 필요합니다.
5. 가족 공간을 만들고, 가족 설정 → 가족 초대에서 **닉네임·이메일로 초대**하거나 **초대 링크**를 보냅니다. 닉네임 초대는 상대가 로그인하면 "초대받은 모임"으로 떠서 한 번에 참여하고(30일), 링크는 열어서 로그인하면 자동 참여합니다(코드 7일, 재발급 시 이전 코드 폐기).

한 계정이 여러 독립 모임에 참여할 수 있습니다. 상단에서 모임을 전환하며, 마지막 공간 선택은 계정별로 해당 기기에 유지됩니다. 각 모임의 멤버·기본 채팅·일정·구매·지출·파일은 독립적입니다. 탈퇴·멤버 제거·소유자 양도 UI는 후속 범위입니다.

- 카드 별칭·가족 구성원별 사용자·수동 등록 한도·월 예산, 카드 설정 수정, 내 카드 필터
- 카드별 혜택 실적 최대 5구간, 전월/당월 실적 기준, 달성 구간과 다음 목표까지 남은 금액
- 분류별 실적 제외, 거래별 제외/인정 금액 수정, 환불 실적 반영 월 지정
- 일별/월별 지출, 환불 음수 입력, 작성자 지출 수정·삭제
- 앱 내 미확인·미완료 알림 모음
- PWA manifest, 아이콘, 홈 화면 설치, 네트워크 단절 안내
- 기본 채팅과 일정·구매별 대화, 기본방으로 일 공유, 기존 지출 연결 및 해당 대화로 복귀
- 모임별 Supabase Realtime 변경 구독, 재연결 후 재조회, 30초/포커스 재조회 보완

파일은 비공개 `haraguri-files` 버킷에 저장합니다. 파일당 10MB, JPG/PNG/WEBP/PDF/TXT/DOCX/XLSX를 허용합니다. 한 가족의 모든 구성원에게 그 가족의 기록·파일이 공유됩니다. 가족 데이터와 파일은 서비스 워커에 캐시하지 않습니다. 현재 앱은 온라인 연결이 필요합니다.

## 용량·수명 설계 (2026-10-27)

- **대화는 방 단위로 100건씩 읽습니다.** 기본 채팅과 일정·구매별 대화의 댓글·첨부는 가족 스냅샷에 포함하지 않고 `lib/chat.ts`가 연 방의 최근 100건만 가져오며, "이전 대화 보기"로 과거 페이지를 이어 붙입니다. 실시간 변경은 열린 방만 다시 읽습니다. 하루 수십 건씩 몇 달을 써도 전체 조회 상한에 걸리지 않습니다.
- **스냅샷 테이블(일정·멤버·확인·카드·지출)은 최신순으로 최대 2,000건.** 상한에 닿으면 앱을 멈추지 않고 최근 2,000건만 표시하며 상단에 안내 띠를 띄웁니다. 지출이 연 1,000건 안팎이라면 2년 이상 여유입니다.
- **사진은 올리기 전에 브라우저에서 줄입니다.** 긴 변 1,600px, JPEG 품질 0.82(`lib/image.ts`). 10MB 휴대폰 사진이 수백 KB가 되어 무료 저장공간 1GB에 사진 2,000~3,000장이 들어갑니다. 400KB 이하 이미지와 PDF·문서는 원본 그대로입니다. 첨부 크기는 `hg_attachments.size`에 기록되고, 가족 설정에서 사용량(%)을 볼 수 있습니다(`hg_storage_usage`).
- **썸네일**: 사진마다 긴 변 320px JPEG 썸네일을 같은 폴더에 `*.thumb.jpg`로 함께 올립니다. 대화 목록은 썸네일만 내려받고, 원본은 눌렀을 때만 받습니다(전송량이 용량보다 먼저 한계에 닿는 항목이라서). 썸네일이 없는 옛 사진은 원본으로 대체합니다. 서명 URL은 방 단위로 한 번에 발급합니다(`createSignedUrls`).
- **대화 종료(2026-10-27)**: 할 일 회차를 완료하거나 구매가 '구매 완료/보류'가 되면 상세 화면이 종료를 제안합니다(자동 아님). 종료하면 그 방은 읽기 전용이 되고 **사진·문서는 삭제, 글은 보존**됩니다. `hg_rooms`가 상태를 들고, 트리거 `hg_guard_closed_room`이 종료된 방의 쓰기를 막습니다. 정리를 위해 첨부·스토리지 삭제 정책은 가족 전체로 열었습니다(업로드는 여전히 본인 폴더만). 다시 열 수 있지만 지운 파일은 돌아오지 않습니다. 종료된 일은 '우리집 일'에서 기본 숨김(종료됨 탭).
- 사진·문서는 한 번에 10개까지 선택해 올릴 수 있습니다. 폰에서는 기본 사진 앱(사진 보관함·카메라)이 바로 열립니다.
- **모임별 저장 한도**: `hg_families.storage_limit`(기본 500MB). 트리거 `hg_guard_storage_quota`가 한도를 넘는 첨부를 거부하고, 가족 설정에 사용률과 80% 경고를 표시합니다. 한도 조정은 대시보드에서 값만 바꾸면 됩니다.
- 실시간이 연결돼 있으면 안전망 폴링을 30초에서 2분으로 늦춥니다.

## 공유 메뉴로 받기 (Android)

- 매니페스트 `share_target` + 서비스 워커가 `POST /share`를 받아 캐시에 잠시 보관하고 `/?shared=1`로 돌려보냅니다. 앱은 항목을 꺼내(10분 지나면 폐기) "공유받은 항목" 창을 띄웁니다. 사진·PDF는 올릴 방(기본 채팅 또는 진행 중인 일)을 고르고, 글은 카드 승인 문자면 가계부로, 아니면 기본 채팅으로 보냅니다.
- 홈 화면에 설치한 Android Chrome에서만 공유 시트에 나타납니다. 서비스 워커가 없는 상태에서 들어온 `POST /share`는 `app/share/route.ts`가 안내 문구와 함께 홈으로 돌립니다. **iPhone Safari는 Web Share Target을 지원하지 않아** 사진을 저장한 뒤 ＋ 사진·문서로 고릅니다. 카카오톡·라인 사진은 두 앱 모두 외부 API가 없어 이 공유 경로가 유일합니다.

## 카드 승인 문자로 지출 채우기

- 지출 기록 창의 "✉ 카드 승인 문자 붙여넣어 채우기"에 문자를 그대로 붙여넣으면 `lib/cardsms.ts`가 금액·날짜·시각·가맹점·카드사·끝 4자리·취소 여부를 뽑아 사용처·금액·날짜·분류·카드를 채웁니다. 누적·잔여 금액은 무시하고, 승인취소는 음수(환불)로 넣습니다. 날짜가 오늘보다 뒤면 작년으로 봅니다.
- 카드 선택은 끝 4자리 → 카드사 이름 → 카드가 하나뿐일 때 순으로 맞추고, 못 맞추면 직접 고르도록 안내합니다. 분류는 가맹점 키워드로 추정합니다(마트·카페 → 식비, 약국 → 의료 …). 저장 전 확인은 사용자 몫이며 자동 저장하지 않습니다.
- 사진 OCR·카드사 연동·CSV 가져오기는 아직 없습니다.

## 일정 수정 규칙

- 모임 멤버 누구나 제목·종류·담당자·예상 금액·메모를 고칠 수 있습니다(가족 앱이라 작성자 한정을 두지 않음).
- 확인·대화·사진·지출 기록이 하나라도 붙은 일정은 **날짜와 반복을 바꿀 수 없습니다.** 회차별 기록이 고아가 되는 것을 막기 위한 규칙이며 DB 트리거(`hg_guard_entry_reschedule`)가 최종 차단합니다. 화면은 미리 잠그고 안내합니다.

## 로그인

- 기본은 카카오(이메일 동의 없이, `email_optional`). 카카오를 쓸 수 없을 때를 위해 로그인 화면에 **이메일 인증(8자리 번호 또는 메일 링크)** 비상 경로가 있습니다.
- 기본 Supabase 발신 서비스는 조직 멤버 이메일에만 보내므로, 가족 구성원에게도 메일 로그인을 열려면 커스텀 SMTP를 연결해야 합니다. 인증 확인을 끄거나 가족을 Supabase 관리자에 초대하는 방식으로 우회하지 않습니다.

## 초대 (2026-10-27)

- **닉네임·이메일 지정 초대** — 모임 주인이 설정 → 가족 초대에 상대의 카카오 닉네임 또는 로그인 이메일을 등록합니다(`hg_invite_targets`, 30일). 상대가 로그인하면 `hg_my_invites()`가 이메일과 카카오 프로필 이름(`name`/`user_name`/`preferred_username` 메타데이터)을 대소문자 무시로 대조해 "초대받은 모임" 카드를 띄우고, [참여하기] → `hg_accept_invite()`로 참여하며 대상 행을 지웁니다. 모임 없음 화면·모든 탭 상단·설정 세 곳에 같은 카드가 뜹니다.
- **초대 링크** — 코드 발급 시 `/?invite=<코드>` 링크를 복사·공유합니다. 링크를 연 사람은 로그인 화면에서 띠를 보고, 로그인 직후 자동으로 참여합니다(코드는 `localStorage`에 임시 보관, 참여 후 삭제).
- **코드만 받았을 때** — 로그인 화면의 "초대 코드를 받았어요"에 코드(또는 링크 전체)를 붙여넣으면 같은 방식으로 기억했다가 로그인 직후 참여합니다. 로그인 뒤 화면(모임 없음·설정)에서도 코드 입력이 됩니다.
- 카카오 닉네임은 상대가 카카오에 설정한 표시 이름 그대로여야 합니다. 띄어쓰기가 다르면 매칭되지 않으니, 애매하면 링크를 보내는 쪽이 확실합니다.

## 푸시 알림 (Web Push, 2026-10-27)

- **흐름**: 브라우저 구독(`lib/push.ts`, VAPID 공개 키) → `hg_push_subscriptions`(본인 행만) → DB 트리거가 `pg_net`으로 Edge Function `push`를 비동기 호출(새 메시지·새 파일) → `web-push`로 발송. 매일 **08:00 KST**(pg_cron `0 23 * * *` UTC) "오늘 챙길 일" 요약을 가족 전원에게 보냅니다. 알림을 누르면 `/?open=일정:회차` 또는 `/?tab=…`로 열립니다. 410/404 응답은 구독을 지웁니다.
- **비밀 값 3곳**(Git 밖): Vercel 환경변수 `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, Edge Function 시크릿 `HOOK_SECRET`·`VAPID_*`, Vault `haraguri_push_url`·`haraguri_push_secret`. 로컬 `.env.push`에 키가 있고 `scripts/setup-push-secrets.sh`가 세 곳에 한 번에 넣습니다. **Vault 값이 없으면 트리거는 아무것도 보내지 않으므로**(no-op) 먼저 배포해도 안전합니다.
- 기기마다 설정 → 알림에서 켭니다. iPhone은 홈 화면에 설치한 앱(16.4+)에서만 가능. 발송 실패는 쓰기(메시지 저장)를 막지 않습니다.

- **iCloud 없는 전달**: `ShortcutFileInstall`은 서명 파일을 미리 준비해 사용자의 클릭 안에서 공유하고, 해당 파일 공유가 미지원이면 일반 다운로드를 유지합니다. `/shortcuts`는 로그인 없이 공개 파일을 받을 수 있는 설치 화면입니다. 수신자가 파일을 저장할 때는 `나의 iPhone`을 선택할 수 있습니다. 실기기에서 파일 형식 인식·공유 화면·로컬 저장 선택까지 확인했으며 단축어 앱 직접 가져오기 완료는 아직 미검증입니다. 공유 창을 닫았다는 이유로 설치 완료로 판정하지 않습니다.
- **실사용 단축어(10/30)**: Mac으로 처음 받은 `하라구리 앱 알림`과 `하라구리 앱 알림 2`는 POST에 전체 알림 토큰이 연결되고 본문 추출이 전송 뒤에 있었습니다. 폰의 활성 `하라구리 앱 알림 2`는 POST `body`를 `알림 → 본문`으로 수정하고 `via=ios-notification`을 추가했습니다. 우리WON뱅킹을 포함한 10개 앱·필터 없음·자동화 켜짐을 확인했고, 개인정보 보호의 `잠겨 있는 동안 실행 허용`도 켜져 있었습니다. 16:16 수동 실행에서 서버 접속 허용 후, 다시 실행할 때 추가 질문 없이 빈 요청이 서버에 도착했습니다. 이 수동 빈 요청은 자동 수집 증거와 구분합니다. 실물 본문 참조는 `TriggerOutput`/`WFNotificationTrigger` + `WFPropertyVariableAggrandizement.PropertyName=Body`이며 생성기는 이 직접 참조 또는 전송 전에 연결된 텍스트 동작만 허용합니다. 구버전 Mac 내보내기에 트리거가 없는 것을 폰의 트리거 유실로 단정하지 않습니다.
- **우리은행 1,700원 복구**: 실제 캡처 원문에서 계좌 메타데이터가 가맹점으로 선택되던 파서를 수정하고 배포했습니다. 가맹점·금액·거래 시각·잔액 제외·중복 처리를 검증했습니다. 누락됐던 한 건은 `notification-replay`로 확인 대기에 복구했으며 실제 자동화 성공 증거로 사용하지 않습니다. 개인 계좌·잔액·토큰과 복구 백업은 공개 문서·배포 파일에 포함하지 않습니다.
- **설정 파일·스크립트 검토(10/30)**: [Apple 프로파일 지원 목록](https://support.apple.com/en-ie/guide/deployment/depdca795ebd/web)에서 일반 사용자 단축어 생성·활성화를 대신하는 payload는 확인되지 않았습니다. [XCUIAutomation](https://developer.apple.com/documentation/XCUIAutomation)으로 개발용 기기 화면 조작을 자동화할 여지는 있지만, [개발자 모드·Mac 연결·사용자 확인](https://developer.apple.com/documentation/xcode/enabling-developer-mode-on-a-device)이 필요해 소비자 설치 경로로는 적합하지 않다고 판단합니다. 프로파일 설치로 전체 제어가 가능하다고 안내하지 않습니다.
- **다른 보조 수단**: [iPhone 미러링](https://support.apple.com/en-ca/guide/iphone/iph505911a40/27/ios/27)으로 같은 Apple 계정의 Mac에서 폰 화면을 조작할 수 있습니다. 이를 화면 클릭 스크립트에 연결하는 것은 가능한 후보지만 기기 연결·인증과 화면 상태에 의존하고, 단축어 설정 전체 제어는 아직 검증하지 않았습니다. [Apple Intelligence의 설명으로 단축어 만들기](https://support.apple.com/guide/iphone/apple-intelligence-stay-organized-dom122pp864g/27/ios/27)도 지원 기기에서 쓸 수 있으나 생성된 트리거·본문·전송 동작의 결과를 확인해야 하므로 검증된 배포 파일을 대신하는 기본 경로로 삼지 않습니다.
- **일반 사용자 설치 단축 재조사(10/30)**: [one sec](https://tutorials.one-sec.app/en/articles/10309122)는 앱 열기 자동화를 가져오기 화면에서 켜고 추가하는 흐름을 제공하며, 미리 구성한 앱의 재선택을 줄입니다. 은행 알림 수집 앱 [Spenvo](https://spenvo.app/setup/)는 알림 트리거·본문 연결을 담은 공유본을 배포하고 사용자는 은행 앱 추가·활성화만 하게 합니다. 따라서 하라구리도 **무토큰 iOS 27 템플릿 공유로 알림 카드 수동 추가를 제거**하는 것이 우선 후보입니다. 한국 은행 앱 선택의 타 기기 보존·가져오기·트리거 유지 검증은 남아 있습니다. [공개 GitHub 트리거 자료](https://github.com/viticci/shortcuts-playground-plugin/blob/main/codex/skills/shortcuts-playground/AUTOMATION_TRIGGERS.md)의 OS 27 타깃 지정은 호스트 서명기 교체가 아니며 현재 Mac 문제를 해결하지 않습니다. 설치와 계정 nonce 전달까지 한 번에 끝내는 검증된 PWA 경로는 찾지 못했습니다. [Apple App Shortcuts](https://developer.apple.com/documentation/appintents/app-shortcuts)를 쓰는 네이티브 앱은 로그인 세션으로 계정 연결을 줄일 후보지만 사용자 자동화 활성화를 없애는 근거는 아닙니다. 오래된 Stack Overflow의 SiriKit·자동화 탭 설명은 iOS 27의 현행 설치 흐름으로 사용하지 않습니다.
- 폴백: iOS 26 이하 기기는 문자(SMS) 트리거, Apple Pay 카드는 거래 트리거, Mac이 있으면 중계기(미러 알림·Mac 카카오톡 알림톡 모두 알림 DB에 본문째 기록됨 — 단 아이폰 미러 알림 전달은 애플 쪽이 간헐적으로 끊기는 사례가 많음). 중계기는 이제 `via`(`mac-relay-sms`/`mac-relay-notif`)와 알림 앱 식별자를 함께 보내 수신함에서 출처가 구분됩니다.

## 카드 결제 정보가 들어오는 네 가지 길 (2026-10-28)

카드사에 직접 물어볼 수는 없습니다(마이데이터 영역). 결제 순간의 **문자·알림**과 **캡처**가 원천이고, 네 길 모두 같은 수집 주소·확인 대기열·지문 중복 제거를 씁니다. 겹쳐 켜도 한 건만 들어갑니다.

1. **문자(SMS)** — 카드사 앱 → 알림 설정에서 "이용내역 알림"을 문자로(앱 푸시와 동시 수신 가능한 곳 많음, 5만 원↑ 대개 무료). 아이폰은 아래 단축어, 갤럭시는 알림 수집 앱(예정), Mac은 중계기.
2. **Apple Pay 거래 트리거(아이폰)** — 지갑에 넣은 카드는 문자 없이도: 단축어 → 자동화 → ＋ → **거래** → 카드 선택 → 즉시 실행 → 동작 **텍스트**: `승인 [금액]원 [가맹점]` (변수는 단축어 입력의 금액·가맹점) → **URL 콘텐츠 가져오기**(POST, JSON `text` = 그 텍스트, URL = 수집 주소).
3. **아이폰 알림 → Mac 중계기(iOS 18 + macOS 15↑)** — Mac에서 **iPhone 미러링** 앱을 한 번 열어 아이폰과 연결하면 시스템 설정 → 알림 → **iPhone 알림 허용**이 생깁니다. 켜면 카드앱 푸시가 Mac 알림센터에 들어오고, 중계기가 알림 DB(`~/Library/Group Containers/group.com.apple.usernoted/db2/db`)에서 결제 문구를 읽어 수집 주소로 보냅니다. 상태는 `~/.haraguri-relay/status.json`의 `notif`(읽기 가능 여부·최근 앱 식별자). Mac이 켜져 있을 때만.
4. **캡처 보충** — 가계부 → 📷 캡처 가져오기, 지출 입력 폼 링크, 또는 안드로이드 공유 시트로 캡처를 넘기면 "거래로 가져오기". 같은 날 같은 금액은 "이미 있음"으로 기본 해제되므로 **수시로 올려 빠진 것만** 채우면 됩니다.

## 아이폰 단축어 자동화 (Mac 없이 문자 → 가계부)

iOS 17 이상이면 "메시지 수신" 자동화가 확인 없이 즉시 실행됩니다(편한가계부·후잉도 같은 방식 안내). Mac 중계기와 같이 켜 둬도 지문(fingerprint)으로 중복은 무시됩니다.

1. 단축어 앱 → **자동화** → ＋ → **메시지**
2. 조건: **보낸 사람**에 카드사 번호를 모은 연락처("카드사")를 고르거나, **메시지 포함**에 `승인` 입력 → **즉시 실행** 선택, "실행 시 알림" 끄기
3. **새로운 빈 자동화** → 동작 **URL 콘텐츠 가져오기**
   - URL: 앱 설정 → 가계부 자동 수집에서 복사한 **수집 주소** 그대로(토큰 포함)
   - 방법 **POST** · 요청 본문 **JSON** → 키 `text`, 값은 변수 **단축어 입력**(메시지 내용)
4. 완료 후 테스트: 다른 폰에서 `승인 1,000원 테스트` 문자 → 가계부 **확인 대기**에 표시 → 거절로 지우면 끝

카드사 알림이 카톡으로만 오면 카드사 앱에서 **문자 알림**으로 바꿔야 합니다(5만 원 이상은 대개 무료, 전액 문자는 카드사별 월 300원 안팎).

## 예산 · 수입 (2026-10-27)

- **예산**: 가계부 요약 첫 칸(또는 홈 게이지) → 총액과 분류별 금액(선택). `hg_budgets`는 모임·월 단위이며 **바꾸기 전까지 다음 달로 이어집니다**. "오늘은 N원까지" = 남은 예산 ÷ 남은 일수. 80%·100%를 넘는 순간 DB 트리거가 모임 전원에게 푸시 1회(알림 설정 "예산 80% · 초과 알림").

## 가계부 2·3차 (2026-10-27)

- **분류 자동 학습**: 지출을 저장하면 가게 이름의 브랜드 단어(예: "스타벅스")가 `hg_category_rules`에 분류·정산범위와 함께 기록되고, 다음 입력과 문자 자동 수집에 적용됩니다. 분류를 직접 고르면 그 입력에서는 규칙이 덮어쓰지 않습니다.
- **취소 상쇄**: 승인취소 문자는 같은 금액·60일 내·비슷한 가게의 원 거래를 찾아 `cancels`/`canceled_by`로 묶습니다. 합계는 음수 행으로 상쇄되고 내역에는 "취소됨/취소" 배지.
- **지출에서 대화 💬**: 연결된 방이 있으면 열고, 없으면 구매 완료 항목을 만들어 지출을 연결한 뒤 그 방을 엽니다.
- **달력 보기·검색·메모·공동/개인·😣 후회**: 내역 헤더의 목록/달력 토글, 필터 안 검색칸, 입력 폼 "자세히" 안의 메모·정산 범위·후회 체크. 후회는 리포트에 합계로.
- **월말 정산**: 공동 지출을 멤버 수로 균등 분할해 "누가 누구에게 얼마"를 계산(송금 횟수 최소화), "정산 완료로 표시"는 `hg_settlements`. 비율 분할은 추후.
- **적립 봉투**: 목표·기한을 가진 봉투에 넣기/꺼내기(`hg_envelope_entries`). 기한이 있으면 이번 달 넣을 금액을 계산하고 멤버별 기여를 보여줍니다.
- **반복 감지**: 같은 곳에 비슷한 금액이 2개월 이상이면 "반복 같아요"로 제안(1탭 등록), 등록된 반복보다 10% 이상 오르면 인상 알림.
- **주간 요약 푸시**: 월요일 08:00 KST, 지난주 합계·지지난주 대비·상위 분류·이달 예산 %. **CSV 내려받기**: 리포트에서 그 달 전체.

## 카드앱 캡처로 가져오기 (2026-10-27)

- 가계부 → 내역 헤더 **📷 캡처 가져오기**(또는 지출 입력 폼의 링크). 카드사·은행·간편결제 앱의 이용내역 화면 캡처를 고르면 **폰 안에서** Tesseract.js(kor+eng)로 글자를 읽고 `lib/ocr.ts`가 거래로 바꿉니다. 사진·텍스트는 서버로 가지 않습니다. 처음 한 번 한글 데이터(약 10MB)를 받습니다.
- 표에서 날짜·사용처·금액·분류를 고치고 넣을 것만 체크 → 카드 선택 → 추가. 같은 날 같은 금액이 이미 있으면 "이미 있음"으로 기본 해제. 저장 행은 `source='ocr'`, 지문 `ocr:날짜:금액:가맹점`으로 같은 캡처를 두 번 넣어도 중복되지 않습니다.
- **✨ AI 정밀 인식(선택)**: 레이아웃이 특이해 온디바이스 결과가 엉성하면, 동의 후 엣지 함수 `vision`이 이미지를 Claude에 보내 JSON으로 받습니다(이미지 미저장). `ANTHROPIC_API_KEY=… scripts/setup-vision-secret.sh`를 실행해야 켜지고, 그 전엔 503과 안내 문구.
- 캡처가 막힌(캡처 방지) 앱 화면은 PC 카드사 홈페이지에서 캡처하거나 CSV를 쓰세요. 실 OCR 회귀 테스트: `OCR_E2E=1 npx vitest run lib/ocr.e2e.test.ts`.

## 아직 구현/검증하지 않은 범위

- **푸시 실기기 수신**: 구조·배포는 끝났고 비밀 값 입력(`scripts/setup-push-secrets.sh`) 후 폰에서 구독·수신을 확인해야 함
- **가족 구성원 메일 로그인(SMTP)**: `supabase/config.toml`에 Resend 템플릿을 주석으로 넣어 둠. 계정 생성 후 `RESEND_API_KEY`를 `.env.kakao`에 넣고 `scripts/configure-kakao.py`로 적용
- 자동 수집의 완전 자동화(iPhone Mac 중계, Android 수집 앱), 사진 OCR, CSV 가져오기
- **카드 자동 연동·실제 잔여 한도**: 수동 등록 한도는 참고값이며 실제 카드사 이용 가능 한도가 아님. 월 잔액은 수동 지출과 월 예산으로만 계산
- 지출 자체의 별도 댓글·첨부(연결된 일에 보관 가능), 반복 지출 자동 생성
- 파일 삭제 UI, 메시지 수정·삭제, 멤버 제거, 본인 표시 이름·모임 이름 변경, 회원 탈퇴·데이터 내보내기
- 첨부가 있는 일정의 삭제: 서버와 화면 모두 차단. 스토리지 정리 흐름 구현 후 제공
- 이전 달에서 넘어온 미완료 항목의 홈 집계(해당 월 캘린더에서 조회 가능)
- 스냅샷 테이블이 2,000건을 넘었을 때의 기간별 서버 집계(현재는 최근 2,000건 표시 + 안내)
- 정기 백업: 무료 플랜은 복구 기능이 없으므로 월 1회 DB 덤프·버킷 내려받기 스크립트 필요
- 실기기 카카오 로그인(iPhone 홈 화면 앱에서 콜백 복귀 포함)은 아직 사람 손으로 확인하지 않음

금액은 원 단위 정수로 기록합니다. 거래일은 현지 날짜 기준이며 결제 취소는 환불 날짜에 음수 거래로 입력합니다. 멤버의 담당자 지정은 필수 완료자를 강제하지 않으며, 누구든 자신의 완료 여부를 기록할 수 있습니다.

## 카드 실적 계산

거래의 실제 날짜는 지출 합계에, 실적 반영 월은 카드 실적에 사용합니다. 실적 반영 월이 비어 있으면 거래 월을 따릅니다. 인정 금액이 직접 지정되면 카드의 분류 제외 규칙보다 우선합니다. 자동 계산 거래는 카드 제외 규칙 변경 시 다시 계산됩니다.

입력 기록을 기반으로 한 추정이므로 실제 카드사의 혜택 확정을 의미하지 않습니다. 이전 달 기록이 없으면 혜택 미달로 확정하지 않고 확인 필요 상태로 표시합니다. 카드 API·OCR·CSV 가져오기는 아직 구현하지 않았습니다.

## 모임·우리집 일·대화 구조 (2026-10-28)

- 계정 하나에 여러 모임이 연결됩니다. `hg_members`의 `(family_id,user_id)`가 멤버십이며, `family_id`는 독립 모임 공간의 경계입니다. 계정별 한 모임 제한은 제거했습니다.
- 기존 `hg_entries`를 공통 일의 기준으로 유지합니다. 일정/할 일에 구매 유형, 예상 금액과 구매 상태를 추가했습니다. 기존 ID·댓글·첨부·반복 회차는 유지합니다.
- 댓글·첨부의 `entry_id`와 `occurrence`가 모두 NULL이면 해당 모임의 기본 채팅방입니다. 둘 다 값이 있으면 해당 일의 회차별 대화입니다. 다른 모임으로의 공유 참조나 지출 연결은 복합 외래 키가 차단합니다.
- 지출은 해당 일/회차에 선택적으로 연결합니다. 기존 지출을 연결할 때 복제하지 않으며 실제 거래일과 일정 날짜는 별개입니다. 예상 금액과 구매 완료 상태는 실제 지출을 자동 생성하지 않습니다.
- 사진은 비공개 버킷에서 서명 URL로 미리보기합니다(10분 유효, 5분마다 갱신). 다운로드 URL은 60초 유효합니다. 사진·지출·공유 참조가 있는 일은 삭제를 막아 기록을 보존합니다.
- 채팅 읽음/안 읽은 개수, 메시지 검색·수정·삭제, 예약 푸시, 이메일 없는 인증 대체는 이번 변경에 포함하지 않았습니다.

### 행사 한정 손님 초대 — 설계만, 미구현

모임 멤버와 행사 손님은 별도 권한이어야 합니다. 행사 손님 초대를 `hg_members` 가입으로 처리하지 않습니다. 후속 구현에서는 행사/회차/사용자 단위 guest membership과 만료·취소 가능한 초대 토큰, 행사 전용 진입 화면이 필요합니다.

손님은 초대받은 행사 안내·전용 대화·명시적으로 공개한 첨부·참석 응답만 접근합니다. 모임 기본방·다른 행사·카드·지출은 기본 비공개입니다. 현재 모임 단위 Storage 정책도 행사 공개 범위를 검사하도록 별도 확장이 필요합니다. 비용·가족 전용 메시지가 손님에게 그대로 노출되지 않도록 기존 대화 전체 공개가 아닌 공개 범위를 명시해야 합니다.
